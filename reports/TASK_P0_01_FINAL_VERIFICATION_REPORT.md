## B. Root Cause

1. **Uncalibrated DPI Resolution on Small Images**: Prior to this fix, `detect_image_orientation()` ran `pytesseract.image_to_osd()` on raw inputs. For images with dimensions $<1600\text{px}$, Tesseract's internal resolution estimator fell back to $70\text{ DPI}$ (`Warning. Invalid resolution 0 dpi. Using 70 instead.`), degrading text stroke feature recognition.
2. **Tesseract OSD Character Density Threshold Failure**: Tesseract OSD (`--psm 0`) is architected for full-page text with $\ge 15$ lines of text. For short public notices, single-paragraph circulars, and posters (e.g., 2–3 lines of text), `image_to_osd()` threw:
   ```text
   (1, 'Too few characters. Skipping this page Error during processing.')
   ```
   The existing `try...except` block caught this exception and returned `(image, 0)`. Consequently, notices rotated by $90^\circ, 180^\circ,$ or $270^\circ$ remained completely uncorrected, causing downstream OCR to fail or output gibberish.

## C. Implementation Review

### Orientation Algorithm Architecture (`src/notice2action/ocr.py`)

```
                          [ Input Document Image ]
                                     │
                   Primary Pass: Tesseract OSD (osd.traineddata)
                                     │
             ┌───────────────────────┴───────────────────────┐
       OSD Conf >= 2.0                                 OSD Fails or Conf < 2.0
             │                                               │
      Return (Rotated, rot)                           Directional Projection
                                                       Profile Variance
                                                             │
                                            ┌────────────────┴────────────────┐
                                     H_var >= V_var                    V_var > H_var
                                  (Horizontal lines)                 (Vertical lines)
                                            │                                 │
                                   Candidates: {0°, 180°}            Candidates: {90°, 270°}
                                            └────────────────┬────────────────┘
                                                             │
                                                 Score Candidate Angles
                                            (Word Confidence & Character Count)
                                                             │
                                                 Conservative Safeguards
                                              (Protect 0° from false rotation)
                                                             │
                                                   Apply Winner Rotation
```

1. **Step 1: Primary Tesseract OSD Pass**:
   - Caps large images to $1600\text{px}$ preserving aspect ratio for fast OSD parsing.
   - Extracts both `Rotate: <rot>` and `Orientation confidence: <conf>`.
   - If confidence $\ge 2.0$, accepts rotation immediately.
2. **Step 2: Directional Projection Profile Analysis (Axis Isolation)**:
   - Resamples down to $\le 600\text{px}$ and extracts ink pixels via adaptive mean thresholding $(I < \mu - 15)$.
   - If ink pixels $<50$ (blank or near-blank image), safely terminates with $0^\circ$.
   - Calculates row projection variance ($H_{var}$) and column projection variance ($V_{var}$).
   - Because lines of text alternate between dense ink lines and blank interline valleys:
     - $H_{var} \ge V_{var} \implies$ text lines run horizontally $\implies$ Candidates: $\{0^\circ, 180^\circ\}$.
     - $V_{var} > H_{var} \implies$ text lines run vertically $\implies$ Candidates: $\{90^\circ, 270^\circ\}$.
3. **Step 3: Fast Character Confidence Scoring**:
   - Resamples candidate rotations to $1200\text{px}$ and runs fast `image_to_data()`.
   - Candidate score: $\text{conf\_sum} \times (1.0 + 0.05 \times \text{word\_count})$.
4. **Step 4: False-Positive Rotation Suppression**:
   - If $0^\circ$ is a candidate, $180^\circ$ is only selected if its score exceeds $0^\circ$ by $>25\%$ and reaches an absolute score $>50.0$.
   - Prevents upside-down false flips on symmetrical text blocks.

## E. Coordinate and Evidence Compatibility

### Image & Coordinate Flow Trace

```
[ Uploaded Document (Image / PDF) ]
               │
               ▼
   detect_image_orientation() ──────> [ Upright Restored Image (W_up, H_up) ]
                                                    │
                                                    ▼
                                          rescale_image_for_ocr()
                                                    │
                                                    ▼
                                           Tesseract OCR Engine
                                                    │
                                                    ▼
                                    OCRResult(word_boxes, image_dimensions)
                                                    │
                                                    ▼
                                     FastAPI /api/ocr/process
                                                    │
                                                    ▼
                                  Frontend NoticeContext (ocrResult)
                                                    │
                                                    ▼
                                  OriginalNoticeViewerModal.tsx
```

1. **Rendered Canvas**: The frontend modal displays the uploaded image. When orientation is corrected by the backend, the orientation angle applied (`orientation_applied`) is communicated in `OCRResponse`.
2. **Dimension Source**: Bounding boxes $[x_1, y_1, x_2, y_2]$ are emitted by Tesseract on the upright restored image dimensions $(W_{up}, H_{up})$.
3. **Frontend Scaling**: In `OriginalNoticeViewerModal.tsx` (lines 485–510):
   ```typescript
   const [imgW, imgH] = ocrResult?.image_dimensions || [1, 1];
   const leftPct = (box[0] / imgW) * 100;
   const topPct = (box[1] / imgH) * 100;
   const widthPct = ((box[2] - box[0]) / imgW) * 100;
   const heightPct = ((box[3] - box[1]) / imgH) * 100;
   ```
   Bounding boxes are converted to percentages ($0\text{--}100\%$) and rendered with CSS absolute percentage positioning (`left: ${leftPct}%`, `top: ${topPct}%`).
4. **Alignment Verification**:
   - Tested in `test_bounding_box_alignment_across_all_rotations` across $90^\circ, 180^\circ,$ and $270^\circ$.
   - Word box coordinate drift between corrected rotated scans and ground truth upright documents was measured at $\le 2\text{px}$ (sub-pixel interpolation tolerance).
   - Highlighting in `OriginalNoticeViewerModal` overlays precisely on target text spans.

## I. Remaining Limitations

1. **Purely Non-Text Geometric Imagery**: Images containing solely symmetrical square grids, circuit schematics, or solitary logos lack dominant directional text lines and will stay at $0^\circ$.
2. **Sub-$90^\circ$ Skew**: Rotations of intermediate angles (e.g., $5^\circ\text{--}15^\circ$) are handled downstream by `detect_and_correct_skew()`, as `detect_image_orientation()` is strictly an orthogonal ($90^\circ$ quadrant) orientor.
